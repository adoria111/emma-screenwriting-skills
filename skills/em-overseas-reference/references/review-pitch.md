# 过稿审查与投稿包装

## 过稿审查：编辑判断而非保证

依据 G01—G07 与案例校准；以下是内部开发标准，不是已经验证的官方收稿门槛。

| 维度 | 核验问题 | 证据应在哪里 |
| --- | --- | --- |
| 卖点与受众 | 一句话能否说清困境、独特关系／规则、期待回报？ | 简介与开篇是否一致 |
| 主线与主动性 | 目标能否贯穿？主角哪次选择改变了结果？ | 关键转折的行动和后果 |
| 人物与关系 | 对手阻力有利益和资源吗？亲近／决裂有驱动力吗？ | 事件顺序与人物知情 |
| 因果与规则 | 谁为何知情？能力是否临时扩张？ | 世界规则、证据来源和首次展示 |
| 节奏与回报 | 重复冲突有新结果吗？钩子是否承接兑现？ | 前后集相接的位置 |
| 情感与爽点 | 压迫后是否有进展？甜戏是否推进关系？ | 可见反击、偏爱、选择或修复 |
| 本土化 | 换名外是否保留合理动机和制度功能？ | 地域、职业、场景、对白 |
| 格式与可拍性 | 人物、动作、对白清楚吗？制作难点是否可承担？ | 正文与当前制作条件 |
| 材料完整 | 梗概结局、集纲、样稿彼此一致吗？ | 真实存在的文件及版本 |
| 目标要求 | 规格和提交渠道是否核实？ | 用户有效要求／当前官方来源 |

问题记录最小单位：`影响等级｜集/场/段位置｜短摘录或原文事实｜问题与影响｜最小修复建议｜是否碰锁定项`。只有已提供部分就限定局部判断。没有发现重大问题可直接说，没有必要制造“至少十项不足”。

分开三种状态：

- **阻断样稿或投稿包进入下一阶段**：必需内容缺失、内部事实相互冲突、锁定项被改变、实际收稿要求明确不符。写清受影响的产物；这不阻碍完成审稿报告本身。
- **建议优化**：有证据的重复、弱行动、弱兑现；审美取舍须说明目标，不冒充硬规范。
- **待核验**：市场适配、平台规则、权利状况、技术可实现性等尚无证据的事项。若不妨碍当前文稿，就不要扩大为全任务阻塞。

## 通用投稿包

G01/G02共同提到作品标签、完整梗概、人物、分集和正文；各自给出的字数与样稿数量不同。本包保留这些材料类别，不硬编码数量。

1. **项目页**：工作名、题材／语言／目标受众、制作方式、计划总集数与单集时长、实际完成范围。
2. **一句话故事及卖点**：人物＋困境＋目标／选择＋差异化；最多保留最能证明项目价值的几项，不堆“顶流爆款”。
3. **人物关系与小传**：欲望、局限、反差、关系冲突；未知年龄不编造，涉及年龄敏感关系先查设定。
4. **完整故事梗概**：开端、关键升级、主要转折、最终解法和结局。另需宣传简介时再做不剧透版本。
5. **已有分集与样稿**：按真实完成度附上；样稿选择能展示核心规则、人物行动与节奏的部分，接收方指定集数时从其要求。
6. **生产与资料说明**：制作负担、授权／原创状态的已知信息、素材来源、版本及待补项。权利未确认写“未提供”，不是擅称无版权风险。

没有指定字数时以清楚、完整且易审阅为准。用户给了“前10集”不能擅改成来源的“约25集”，也不能因目标未知声称“所有平台统一收这种包”。

## 现行接收条件核验

按需要填：

`平台品牌／实际收稿主体｜国家与语种｜收剧本还是成片｜真人或AI｜收稿是否开放｜官方入口／联系人来源｜核验日期｜格式和样稿数量｜权利要求｜报酬条件原文｜仍待确认`

G06提及 ReelShort、DramaBox、FlickReels、GoodShort、PineDrama、MoboReels、ShortMax、FlexTV、听花岛、麦芽、掌阅、中文在线等，只能作后续核查搜索词；其公司归属、偏好、合作模式和金额均未核验。资料没有可靠投稿邮箱或直接投稿网址，剪存工具推广微信不能作为收稿联系人。

要给当前渠道建议或准备实际投递时，查询目标方官方入口或有效商务要求，引用精确页面及日期。无法确认则完成可独立制作的投稿文案并列最小待补项，不编造渠道。资料中的“原创最高10万”“改编3w起”没有币种、适用期和合同前提，不可作报价。

审稿结论可用“建议进入投稿准备／修改后再准备／材料不足仅局部判断”，不能写成平台通过、签约概率或收入保证。实际投递是另一项外部动作，制作包本身不触发。
