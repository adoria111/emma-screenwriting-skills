# 进度条模板填充

复制 `assets/progress-template.html` 到交付文件，将下面标记全部替换。CSS与渲染脚本已内嵌，保留原布局，主要替换内容；可用本地文本工具生成最终单文件，不依赖指定运行时或网络包。

## 页面字段

- `__TITLE__`：页面标题。
- `__EDITION__`：简短版本或用途。
- `__NAV__`：可选的切换链接HTML，使用`.tab`，当前项`aria-current="page"`；单报告可置空。
- `__THEME__`：主线题材标签。
- `__HEADING__`：易读剧名或分析标题。
- `__SUBTITLE__`：正式剧名或简短副标题。
- `__INTRO__`：一两句主驱动。
- `__HINT__`：一行点击提示，必要时区别付费点与分析分段。
- `__FOOTER__`：简短来源及折叠的范围、分线说明HTML。
- `__DATA__`：下面的数据对象，序列化JSON后将`</`转为`<\/`，再嵌入application/json节点，不对整个JSON做HTML转义。
- `__STATIC__`：所有卡的完整静态HTML，用于打印与“展开全部”。
- `__FALLBACK__`：同一完整内容的无脚本版本，所有ID与静态版、交互版区分。

除特别说明的HTML与JSON字段，其余均以纯文字做HTML转义后替换。占位符全部替换后才能交付，不能把模板当成完成报告。

## 数据对象

顶层为 `{"cards":[...]}`。可选 `rewardLabel`、`chainLabel` 调整诊断模式的小标题。每张卡：

```json
{
  "label":"第一卡",
  "range":"第1—9集",
  "title":"简短的阶段目标",
  "state":"旧状态 → 新状态",
  "reward":"一句话说明实际兑现了什么。",
  "goal":"角色想达到什么。",
  "viewer":"观众在等什么，作为结构判断。",
  "chains":[
    {
      "title":"一项必要条件",
      "nodes":[{"text":"起始需求"},{"text":"具体行动"},{"text":"条件形成"}],
      "why":"一句话解释这条推进的机制。"
    }
  ],
  "emotion":"一两句说明情感触发、变化与驱动力。",
  "bridgeLabel":"为什么还要有下一卡",
  "bridge":"上一卡的结果或遗留怎样促成下一卡。",
  "deep":"生成器构建的折叠详情HTML。"
}
```

填入`state`和`reward`后，回到对应的首尾场核对：`state`左端不能使用本卡中段才发生的加冕、相认等结果；右端与`reward`不能把计划或承诺写成已执行。下一卡的兑现可写进`bridge`或标注为后续回收，不提前计入本卡。用实际事件位置检查，不只检查集数范围和字段是否齐全。

断点节点可加 `"issue":"L1"`，模板添加浅棕提示与编号；具体问题放入deep的details，不能只靠颜色区分。

## 详细层与证据定位

deep直接插入HTML，只能放生成器构建的安全内容，源稿文字须先转义。用details/summary组织集纲、必要条件、箭头机制、双方情感、材料冲突与逐场记录。

内置证据跳转的目标示例为`id="live-scene-1-1"`，链接为`href="#live-scene-1-1" data-ref="scene-1-1"`。点击后自动打开目标及父级details。跨卡引用须在当前卡的折叠附表中提供目标，或另实现可靠定位，不能留下失效锚点。

静态与无脚本版使用不同ID前缀，并同步改写href；不保留交互版data-ref。全部阶段由同一数据生成，证据可在静态末尾集中放一次。不要只输出第一卡回退内容。

交付前确认无残余占位符，JSON可解析，锚点对应，全部阶段与集纲可展开，无远程依赖。检查首层依然是“细条进度＋横向短链”，详细论证收在下层。
